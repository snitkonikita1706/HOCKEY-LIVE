# HOCKEY LIVE 4.0 · iPhone (alpha)

Нативное приложение React Native + Expo Router (SDK 58), разрабатываемое отдельно от действующего сайта.

## Архитектура

- `app/(tabs)/` — четыре нативных раздела: главная, матчи, клубы, избранное;
- `app/match/[id].tsx` — отдельный экран матча;
- `src/api.ts` — адаптеры источников NHL / KHL / KLHL;
- `src/types.ts` — общая доменная модель матча;
- `src/context.tsx` — состояние, загрузка, избранное, сохраняемое на устройстве через AsyncStorage;
- `src/components.tsx` / `src/theme.ts` — UI и дизайн-система.

## Запуск

Нужен Node.js 22.13+ и npm.

```bash
cd mobile
npm install
npx expo install --fix
npx expo start
```

Для iPhone: подключить Expo Go совместимой версии или создать development build. Для App Store потребуется подключённый Expo/EAS-проект и Apple Developer; `npx eas-cli@latest build --platform ios --profile production`.

## Источники данных

- НХЛ: `https://api-web.nhle.com/v1/score/now` и `https://api-web.nhle.com/v1/schedule/now` — результаты, LIVE и недельное расписание;
- КХЛ: `https://snitkonikita1706.github.io/HOCKEY-LIVE/data/khl.json` — периодически обновляемая выгрузка;
- КЛХЛ: `https://snitkonikita1706.github.io/HOCKEY-LIVE/data/klhl.json` — архивная выборка, **не live**.

Экран просмотра ведёт на официальные видеосервисы. Права на трансляции не предоставлены приложению; встраивание платных потоков не реализовано.

## Состояние

Первый кодовый MVP; **ещё не проверен на физическом iPhone и не собран в IPA/TestFlight**. Нет авторизации, серверной БД, push и полной статистики. Избранное сохраняется локально; при переустановке приложения может быть потеряно. Перед релизом нужны тестирование, надёжные лицензированные источники данных и проверка прав на эмблемы и видео.

## Безопасность релиза

Текущий сайт в корне репозитория не изменяется. Работа ведётся в ветке `feature/hockey-live-4-ios`. Объединение с `main` — после тестирования.

## Обновление данных и избранное

- При открытии приложения, возвращении на передний план и каждые 90 секунд активной работы обновляются данные матчей.
- Результаты КХЛ обновляются по графику исходной выгрузки; КЛХЛ — архивные, поэтому 90 секунд не означают, что эти лиги LIVE.
- Избранное сохраняется локально с помощью AsyncStorage 2.2.0 (без регистрации и облачной синхронизации).
- Перед установкой на iPhone проверьте Expo SDK 58 и корректную совместимость сборки с выбранным устройством.

## Обновление 4.0 Alpha.3

- На экране «Матчи» реализован календарь по датам (стрелки для перехода, нажатие на дату сбрасывает фильтр).
- Последний загруженный календарь сохраняется через AsyncStorage и доступен при отсутствии сети. Показывается предупреждение об офлайн-данных.
- Если временно недоступна одна из лиг, её ранее сохранённые игры не исчезают из списка.
- НХЛ загружается одновременно из недельного расписания и табло актуальных результатов; данные табло имеют приоритет для совпадающих матчей.
- Это локальный офлайн-кэш, а не офлайн-видеотрансляции. Источники КХЛ и КЛХЛ обновляются в собственном темпе.

## Подготовка к App Store — Alpha.4

- Добавлены фирменная иконка (`assets/icon.png`) и экран запуска (`assets/splash-icon.png`) из существующей иконки веб-версии. Сейчас исходные файлы 512×512; перед отправкой в App Store желательно подготовить отдельный исходник 1024×1024 и проверить его на iPhone.
- Параметры `expo.ios.bundleIdentifier=kz.snitko.hockeylive` и `buildNumber=1` указаны как стартовая конфигурация; нужно подтвердить уникальность идентификатора в Apple Developer.
- Добавлена вкладка «Настройки» и доступный без сети экран конфиденциальности. Текст политики отражает функции текущей alpha-версии; перед публикацией проверить его на соответствие фактическим SDK и хостингу.
- **Не добавляйте фиктивный EAS project ID**. После явного подключения аккаунта Expo запустите из `mobile/` команды `npx eas-cli@latest login`, `npx eas-cli@latest init`, а затем `npx eas-cli@latest build -p ios --profile preview` для тестовой сборки.
- Для установки на реальные устройства / TestFlight потребуется Apple Developer, корректная подпись iOS, регистрация приложения и корректные сведения о правах на видео/эмблемы.
- Важно: `expo export --platform ios` проверяет JS-экспорт, **не является** нативной iOS-сборкой и не подтверждает прохождение App Review.

## Alpha.5 — нативная конфигурация и выпуск TestFlight

- В CI добавлена проверка `expo prebuild --platform ios --no-install --non-interactive`: создание Xcode-проекта из Expo конфигурации. Это **не** компиляция Xcode и **не** подписанная IPA.
- Для загрузки в **TestFlight** используйте профиль `production` с `distribution: store`, а не `preview`, который предназначен для внутреннего распространения.
- Генератор `.github/workflows/mobile-ios-assets.yml` создаёт iOS иконку 1024×1024 PNG без прозрачности из текущего проекта, а также splash 1024×1024. Увеличение 512→1024 не добавляет деталей: перед релизом желателен качественный оригинал.
- Для публикации потребуется Apple Developer Program, подключение EAS к вашему Expo аккаунту и управление подписными сертификатами — ключи и пароли не нужно добавлять в публичный репозиторий.
- Подробный план — `mobile/APP_STORE_CHECKLIST.md`.
